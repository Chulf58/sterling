## Authority (the knowledge base is the source of truth)

- **The store holds what is *true now***. Consult it before acting; it supersedes memory, this file's summaries and any standalone document.
- **What lives where:** what an area does, its acceptance criteria, which files it owns → **`feature_article`** (filter by `file_keys`). Why it is that way, rejected alternatives → **`decision`**. What not to do → **`anti_pattern`**. Findings with currency → **`research_finding`** — one that measured only PART of its subject states the population and its exclusions in `answer`, because an unstated gap reads as "measured the whole question". External docs → **`reference_material`**. Board and queue → `board_query`, the TUI.
- **Ambiguity → query the store, then ask.** If it is silent or self-contradictory, stop and ask — never improvise around a gap.
- **A query result is a WINDOW, not an inventory.** `capped: true` means more matched — raise `cap` or narrow the filter; never infer absence from a capped result. `knowledge_get` is the full-fidelity read.
- **`knowledge_preflight(text)` is the pre-write conflict check.** It takes no `file_keys` — it answers for a SUBJECT. Run it before drafting a record, before a design settles and before putting a question to the user; a `verify_targets` verdict names the governing records to open BEFORE you proceed. **Phrase the text in the domain's own terms:** the matcher is lexical and a paraphrase misses. After an `ungoverned` verdict on a subject you expect to be governed, re-ask once with the store's vocabulary: its titles' words, sibling record names (decision `pull-quality-closed-at-the-floor-of-retrieval-mechanics-phrasing-rule-no-new-mechanism`).

## Reconcile-always (every affected article, every change)

- **Every change updates the knowledge base to match, before the work is done.** An un-reconciled change makes the store lie; that is drift, and drift is what breaks the store's authority.
- **Reconcile _every affected_ article, not just the primary one** — the owner of the touched files (`what_it_does`, acceptance criteria, `files[]`, a history entry) **and** any article whose described behavior or dependencies the change invalidates; follow `relies_on` / `relied_by`. New features get a new owning article; renames rewrite `file_keys` so knowledge is never orphaned.
- **Which field carries paths is PER TYPE:** `feature_article` → `files[{path, role}]`; `decision`/`anti_pattern`/`research_finding`/`todo` → `file_keys[]`; `reference_material` → `location`. A field the type does not define is refused, never silently dropped.
- **Fix a wrong record FORWARD** with `knowledge_update` — the correction supersedes the error. **Retirement is narrow:** `knowledge_retire(id, in_favor_of)` is for a genuine DUPLICATE, never for a record that is merely wrong, and never by creating a replacement beside the original. **Ask the schema, don't guess it** (`knowledge_schema`), and take the refusal as the authority over the projection. An 8-char prefix resolves when reading and updating; every destroying path (`board_remove`, `maintenance_remove`) demands the full id. **Versioned writes take `expected_version`** — a stale token refuses naming both versions rather than silently overwriting.
- **Author records to be found.** Titles carry the words a user would say, not changelog prose; triggers and statements are short and subject-dense, with evidence moved to `guidance`, `right_way` or `rationale`; one subject per record; accurate file paths. Push and preflight match only a record's narrow fields (title plus statement or trigger), so a subject that sits only in the body is never found. Decision `make-records-findable-authoring-rule-disclosure-lint-then-blind-experiment`, measured in finding `what-makes-a-record-findable-authoring-traits-astra-fable-october-2026`.
- **A capture declaration is LANE-SCOPED.** `no_capture` discharges the capture duty only — a bare declaration never clears the research duty. When the substance exists but its write is still in flight, declare `capture_pending` naming the target instead: pending work defers or lands on the queue, it never evaporates.

## Conduct rules (Sterling layer)

- **A settled ruling is not a fresh choice.** Never offer a choice between implementations of a behavior a decision or ruling index already names — read the deciding paragraph first; presenting a settled question as open manufactures a false ruling when the user picks.
- **Cite rulings by SLUG in durable pointers** (commit messages, dispatch briefs, article prose, this file): a slug names the concept and survives supersession; ids version-pin. Where space allows print both — `[slug] (knowledge_get <id>)`. Bare ids stay correct for mechanically-resolved surfaces (spawn inputs, tool parameters) and for history entries deliberately pinned to what was live then.
- **Never put a bare id in front of a HUMAN.** Any identifier shown to a person carries its human-readable name beside it — `name (id8)`, name first: names clip, ids never do. Asked to rule on "board 17204d1e", the reader has no way of knowing what that refers to, and an unanswerable question still manufactures a ruling.

Before the question reaches the user, run `knowledge_preflight(text)` on its subject — a `verify_targets` verdict means the store already governs it; fold the ruling into the question (or drop it) BEFORE asking.

## Plugin mechanics — surprises worth knowing up front

<!-- claude-only -->
- **A user-scope MCP server entry can be silently dropped under `--strict-mcp-config`.** Launched with that flag, Claude Code honors only the MCP entries explicitly supplied via `--mcp-config` — user-scope entries (and any other entry not passed that way) are ignored with no visible error. If an expected MCP tool never shows up, check the entry's scope before assuming it's misconfigured elsewhere.
<!-- /claude-only -->
