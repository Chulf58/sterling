# Planning SOP (§7.6)

Read-only discipline throughout (plan-mode-shaped — adjudicated; native plan
mode is not load-bearing, §16.2 step 8). Iterable steps; each output is a required brief section:

1. **Technical design.** Pre-dispatch the implementation-architect when complexity is visible at intake (the common case). Dispatch explorer/researcher for heavy reads. Small bounded questions: inline lookups (web + knowledge tools) are licensed — capture findings; big unknowns → researcher. Output: `technical_design` (approach, interfaces with contracts, shared structures).
2. **Decomposition into phases**, informed by the design. Re-read blast radius if the design widened scope. Each phase spec declares its `files` + `rank_terms` — prep's staging inputs are planning outputs, never improvised at staging time. Every phase's interfaces must be declared (the test-writer's spawn fails loud otherwise). Breadth rule: every phase stays within `config.difficulty.split_interface_threshold` (default 3) interfaces; over that ⇒ split the phase before the gate — the `phase_over_wide` flag reports it, and prep and H8 refuse to stage or dispatch an over-wide phase. **Slice/phase lists are agreed in UNBLOCK ORDER, weighed with risk-retirement** (decision `slice-ordering-is-unblock-first`; sharpened by external-model consult): order by unblocking power, not by how foundational a unit feels — the first slice is the one whose completion enables the most independent work to follow — but a risky integration proof can still earn first position even when it unlocks little, and a low-unlock mandatory slice gets a latest-start bound so it never starves. Each next slice is re-picked the same way on material events (a slice lands, a dependency changes, new work surfaces), so the set of runnable work widens like a pyramid as the objective proceeds rather than staying single-file. **Sizing is a second, orthogonal call at the same step** (decision `slice-sizing-token-economy`): on ENFORCEMENT or hook territory keep slice-per-settled-decision, because a hook goes live from disk the moment it lands, so small slices keep interference diagnosable; EVERYWHERE ELSE size UP — one slice is the largest coherent unit one coder dispatch and one review fan-out can carry without spanning unrelated mechanisms, and a small related change rides an adjacent slice's commit cycle rather than minting its own review/rebuild/commit/reconcile ceremony.
3. **AC formalization + flags.** ACs as observable end-to-end behavior, each with `verifiable_at`. Difficulty is the PLANNER'S call, made with cited reasons against the depth inputs (prep retrieval volume vs `thin_knowledge_retrieval_threshold`, algorithmic complexity, ambiguity residue, poorly-covered external integration) — the human is never asked to determine hardness (decision a48c74cf). DEFAULT TO NORMAL when the depth inputs don't clearly indicate hard; under-rating is detected mechanically by the loop caps (§5.1) and answered by upgrade or re-scope, never guessed up front. Bigness is NOT hardness: an over-wide phase SPLITS, it never upgrades. Risk flags `security_relevant`/`perf_sensitive` proposed here, human-confirmed at the gate.
4. **Brief assembly + decision capture.** Design decisions → decision records, cited in `decisions_made`. **Carry the grill's concept inventory into `blast_radius.reconcile_list`** (decision `7208729b`): every concept article the grill created or flagged (grill-intent step 4) lands there by UUID — that field is what completeness-check and the disposal gate enforce, so an inventory that never reaches it has no teeth. If the design surfaced a NEW concept family the grill missed, create its concept article now (the read-only discipline binds the working tree, not the store) and list it too.

**Feature-sizing check:** a feature too big to plan in one conversation is split into features (P7). The brief's AC + scope sections lock at the gate — hooks will enforce them for hours. Re-scope, don't resume: a phase that proves over-scoped mid-run is re-scoped (split) and redone, never stopped and resumed — a resume compounds an already-large context (P7).
